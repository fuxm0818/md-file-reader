# 音色库与符号清理测试用例 · v1.2.0

> 本文件是**唯一真实来源**：用例规格、步骤与预期结果以此为准；
> `templates/TEST-EXECUTION-TRACKING.csv` 只记录执行状态，由 pytest hook 自动回写。
> 对应实现：`src/core/voices.py`、`src/core/textclean.py`、`src/ui/voice_dialog.py`、
> `src/ui/widgets.py`、`src/controller.py`。

## 背景与验收目标

用户反馈两条具体问题：

1. 「声音还是有点太机械」——查证后发现配置里存的是 `Tingting`，那是机械感最强的第一代中文音色，
   而音色在下拉框里以 `Sandy (中文（中国大陆）)  [zh_CN]` 的形式出现，普通人无法据此选择。
2. 「读书的时候有些事不需要读，例如 - 和 /」——符号没有清理层，`say` 会把它们念成「斜杠」「破折号」。

本轮目标：把音色变成**按听感描述的选项**（带逐条试听），并补一层**符号清理**。

### 实测依据

符号是否被读出，用「插入符号 vs 不插」的合成时长差判定（同音色、`-r 200`、Δ>0.06s 视为读出）：

| 结果 | 符号 |
|---|---|
| 会被念出来 | `/` `\` `|` `_` `>` `^` `~` `-` `—` `%` `@` `.` `*` `#` `$` `=` `…` `–` `+` `&` `①` |
| 不发音 | `<` `[` `]` `{` `}` `(` `)` `【` `】` `《` `》` · `•` |

其中 `/` 影响最大（Δ+0.640s），`\` Δ+0.624s，`|`/`_`/`>` Δ+0.560s。

音色音高为实测中位基频（自相关，60–400 Hz，采样率 22050）：`Rocko 89Hz`、`Grandpa 95Hz`、
`Reed 102Hz`、`Eddy/Grandma 116Hz`、`Shelley 167Hz`、`Flo 218Hz`、`Tingting 245Hz`、`Sandy 249Hz`。

## TC-VOI-001 · P0 · 音色标识翻译为可读档案

**前置**：`src.core.voices` 与 `src.core.speech` 可导入。
**步骤**
1. 取系统音色列表中任一中文音色（如 `Sandy (中文（中国大陆）)`）。
2. 调用 `profile_of(voice)` 与 `describe(voice)`。

**预期**
- `base_name()` 把 `Sandy (中文（中国大陆）)` 还原为 `Sandy`。
- 档案含中文名、性别、实测基频、音高档位（≤130 低沉 / ≤200 中性 / >200 清亮）。
- `describe()` 输出形如 `桑迪 · 女声 · 清亮`，不含 `zh_CN` 这类内部代码。
- 未知音色不抛异常，退化为原始名称且音高标记为未测。

## TC-VOI-006 · P0 · 符号清理：念得出来的装饰符号被移除

**步骤**：对下列输入调用 `clean_symbols()`。

| 输入 | 期望 |
|---|---|
| `安装到 /usr/local/bin 目录` | 不含 `/`，`usr`、`local`、`bin` 之间断开 |
| `姓名\|年龄\|城市` | 不含 `\|` |
| `第 3-5 章` | `3到5` |
| `3/4 的用户` | `3比4` |
| `他来了——然后又走了` | 破折号变逗号停顿 |
| `等等……还没结束` | 省略号变逗号停顿 |
| `## 二级标题` | 去掉 `##` |
| `- 第一项` | 去掉列表符号 |
| `1.5 秒之后开始` | `1.5` 不得被当成有序列表编号吞掉 |
| `-----` | 整行只有装饰符号时返回空串 |
| `----- 分隔 -----` | 两端横线去掉，保留「分隔」 |

**预期**
- 上表逐条成立；输出中不再出现 `\ | _ ^ * # $ @ ~` 等会被念出的符号。
- `1.5`、`3.5%` 这类小数点不得被破坏。
- 整行只有装饰符号时返回空串，由调用方回退到原文，不会产生静音句。
- 表格竖线在句子里被规范为空格（长度不变），因此 `display_text` 切片与 `sentence.text` 逐字符可能不同，但区间长度与位置必须一致。

## TC-VOI-007 · P1 · 清理不改变正文显示与句子坐标

**步骤**

2. 对比 `sentence.text`（显示）与 `controller._speech_text(i)`（合成）。
3. 检查 `doc.display_text` 的切片坐标。

**预期**

- 句子坐标仍能在 `display_text` 上准确切片（高亮与跳转不会错位）。

## TC-VOI-010 · P0 · 系统语音输出经打磨为 wav 且响度达标

**前置**：本机有可用的中文系统音色。
**步骤**
1. 用一句带随机后缀的文本调用 `SpeechEngine.synthesize()`。
2. 读取输出文件的容器格式、采样率、峰值与首尾样本。

**预期**
- 输出后缀为 `.wav`（而不是 `say` 原始的 `.aiff`）。
- 峰值落在 -3.5 ~ -0.5 dBFS：`say` 原始输出只有 -3 dBFS 左右的峰值、
  -18 dBFS 的整体电平，打磨后提约 3 dB。
- 首尾样本幅度 < 0.05：淡入淡出生效，切换句子不再"啪"。
- 意义：这是 v1.4 保留下来唯一的声音改进，必须证明它在冻结包和源码里都真的跑了。

## TC-VOI-011 · P1 · 升级时清理一次旧版音频缓存

**前置**：状态文件中没有 `cache_schema`（v1.3 及更早的配置）。
**步骤**
1. 拦截 `SpeechEngine.clear_cache` 记录调用次数。
2. 构造控制器，再构造第二个控制器。

**预期**
- 第一次构造调用一次清理，`cache_schema` 写入当前值，启动提示含"旧版音频缓存"。
- 第二次构造不再清理：缓存不能每次启动都被删空。
- 意义：v1.4 换了缓存键与容器（aiff → 打磨后的 wav），旧文件永远不会再命中。
  本机实测残留 87 MB，不清就是白占硬盘。
